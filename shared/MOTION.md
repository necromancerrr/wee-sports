# Motion contracts and compatibility

`motion.js` is pure JavaScript shared by the browser and optional Expo controller. Samples use monotonic receipt time in seconds, radians per second, metres per second squared, and Hamilton quaternions `{x,y,z,w}`. The phone frame is X to the right edge, Y toward the top, Z out of the screen. `screenAngle` is retained separately; new paddle control applies the explicit screen transform. Missing sensors stay absent. Total acceleration is not called gravity unless linear acceleration can be subtracted.

`normalizeWebMotion` maps browser rotation-rate beta → X, gamma → Y, alpha → Z, converting degrees to radians. `normalizeNativeGyroscope` keeps native Gyroscope X/Y/Z and radians unchanged. `toLegacyMotionSample` reverses the browser mapping and returns the existing millisecond/degree fields. Existing tennis and bowling recognizer thresholds are unchanged. All five selected team-motion recordings pass through this round trip without changing recognized labels or peaks.

There is an existing axis inconsistency to verify on real phones: `src/controller/motionGestures.js` describes `rotationAlpha` as X, while the actual browser code populated it from `DeviceMotionEvent.rotationRate.alpha`. [MDN identifies that browser property as Z](https://developer.mozilla.org/en-US/docs/Web/API/DeviceMotionEventRotationRate/alpha), as does the installed TypeScript DOM declaration. Expo SDK 58's `DeviceMotion.rotationRate` uses different documented names (alpha=X, beta=Y, gamma=Z); it is not the browser API. The native adapter uses Expo **Gyroscope**, avoiding that ambiguous naming. No axis-specific recognizer threshold or direction is silently changed by this extraction. Synthetic equivalence proves the mathematical conversion, not correct physical grips or forward-release behavior. Record forward/backswing and wrist-twist checks on iOS and Android before claiming physical parity or retuning either client.

`createMotionCalibration` requires a continuous stillness window and estimates bias in rad/s. Calibration is local and carries a screen angle/revision; `applyMotionCalibration` rejects a changed screen orientation. The legacy controller continues using its existing calibration behavior. `createPaddleIntentController` outputs normalized orientation `[x,y,z,w]`, bounded reach and angular intent; it does not integrate acceleration into hand position. Duplicate samples are ignored; gaps, new calibration revisions and screen changes clear partial movement. Recenter/first resumed samples have zero angular velocity. The host determines contact and score.

`createTimeConstantFilter` uses `1 - exp(-dt/tau)`, so the same stationary target has the same response at 30, 60 and 100 Hz. It holds on out-of-order samples and resets after a long gap. Bowling's 0.084-second time constant approximates the old 0.18 update at 60 Hz; it is not a measured hardware tuning result.

`createWebMotionAdapter` owns permission, browser motion/orientation subscriptions, visibility and page lifecycle. Start it directly from a player action. It does not infer successful calibration from permission. Optional orientation permission failure keeps gyro/touch usable. Dispose removes every listener. The existing controller uses `readLegacyWebMotion` so its established UI/permission sequence is preserved; the new paddle controller can use the complete adapter.

`createMotionRecorder` is an explicit local bounded recorder. It whitelists sample fields and does not retain room/account tokens or upload data. `controllerCapabilities.js` negotiates protocol minor version, sport versions and optional capabilities. Legacy clients retain tennis/bowling; table tennis requires an explicit compatible offer. Missing haptics do not block touch-capable play.

Run `node scripts/replay-motion.mjs > /tmp/wee-motion-report.json` to reproduce recognition measurements. Its report includes fixture Git blob and SHA-256 hashes, commit/runtime, sample counts, mode, confirmation timestamps and min/median/p95/max. These are offline recognition measurements; they do not measure phone capture, network travel, host contact, display latency or actuator onset. `npx vitest run server/shared-motion.test.js` verifies unit/sign conversion, the recorded traces, time-based filtering, calibration continuity, pause/recenter behavior, trace privacy, permission cancellation and capability negotiation.
